# 站点建设方案 · 怎么比别人做得好

> 2026-10-29 整理。**这份文件管“网站怎么做”，不管“小说怎么写”**（写作另见 `docs/story-bible.md`、`docs/reference-danmachi.md`）。

---

## 一、先定判据（所有“更好”都要落到这三条）

1. **三秒**：打开首页，知道这是哪本书、什么调子、点哪里开始读。
2. **三分钟**：能在手机上读完第一章，不卡、不跳、不需要注册。
3. **三章**：读完三章后，愿意把链接发给别人 / 加书签。

做不到这三条，任何视觉或功能加分都不算数。

---

## 二、对标：别人怎么做，我们怎么做

| 维度 | 日系轻小说站常见做法（カクヨム / なろう / GA / 电击 / 角川系官网） | 我们现在的做法 | 我们的优势在哪 |
|---|---|---|---|
| 首屏 | 巨大横幅 + 一堆新刊轮播 + 排行榜 | 满幅插画 + 书名 + 两句定位 + 一个按钮 | 只有一个动作，不逼读者做选择 |
| 进站 | 直接进首页 | **首访门**：点猫 → 走进画面 → 才到首页 | 把“进入”做成叙事，不是弹窗 |
| 目录 | 章节列表 + 更新日 + 简介 | 卷 → 章，每行带字数与阅读时长；前言单独一块、放在卷末 | 读者一眼知道“读完这一章要多久” |
| 阅读器 | 正文字号固定，或需登录记住进度 | 字号 16/18/20、行宽 33/38 字（切换**一眼可见收窄**）、纸色/夜读、进度自动记 | 不需要账号也能“记住你” |
| 档案 | 头像 + 三行简介，或外链 wiki | **画师设定原稿整张**（460px 常驻）+ 分栏文字 + 按读到第几章解锁 | 设定本身就是可看的内容 |
| 世界观 | 词条列表 / 年表 | **三份互相矛盾的史料**（正典 / 残卷 / 账页）+ 教会等级 + 年表，不告诉读者谁对 | 读者自己拼图，讨论欲更强 |
| 更新 | 靠编辑后台 / WordPress | 站内 `/admin/` 写稿台 → D1 → 线上立刻可见 | 作者本人不需要碰 Git |
| 性能 | 图片大、字体多、首屏 2–4MB | 字体子集化（四百字）、AVIF/WebP、首屏 ≈145KB | 弱网也能开 |
| 文案 | 官方腔、术语多 | 全站零内部词（AI/预览/占位/素材）、零“教程式提示” | 不像 demo 站 |

## 三、十个差异化点（每条都写清“怎么验证”）

| # | 差异点 | 怎么验证（可量化） |
|---|---|---|
| 1 | **无账号记忆**：进度与已解锁人物存在本地 | 清缓存前刷新 3 次，进目录仍显示“继续读 · 已读 62%” |
| 2 | **阅读器可调**：字号/行宽/主题 | 切“窄”档，正文栏宽从 684px 收到 428px（手机 328→236），肉眼可见 |
| 3 | **首访门**：一次会话只出现一次 | 关掉标签页 10 分钟内重开，不再出现 |
| 4 | **设定原稿上站**：460px 常驻、点开看大图 | 手机端整幅显示，无横向滚动条 |
| 5 | **图鉴按进度解锁**：未读到只显示剪影与“读到第 N 章” | 读第 1 章前 0/12，读完后 5/12，开“剧透模式”12/12 |
| 6 | **前言是史料不是百科**：三份矛盾文本 + 六个神位 + 教会等级 | 通读一遍，读者能说出“正典/残卷/账页各是谁的立场” |
| 7 | **写作后台在站内**：`/admin/` 口令进入，写完即发 | 改一个字 → 保存 → 刷新读者页可见（无需部署） |
| 8 | **性能预算**：首屏 ≤150KB、单张插画 ≤260KB | Chrome Network 面板冷启动读数 |
| 9 | **命名与文案纪律**：无内部词、无教程腔、无占位图 | 全站 grep：AI/预览/占位/素材/PSD/dpi = 0 |
| 10 | **章节纪律（写作侧）**：2,500–2,900 字、短段 ≥65%、每章一处“出丑或被反将”、双审后才发 | 每章交付附指标表 + 双审记录 |

> 注：第 10 条属于写作，但**它是站点体验的一部分**——读者对“读得下去”的判断发生在正文里。

## 四、路线（P0 → P7）

| 优先级 | 做什么 | 现状 | 代价 | 验收 |
|---|---|---|---|---|
| **P0** | 继续写正文（第 5 章起） | 4 章 / 10,820 字已上线 | 每章 ¥1.5 | 每章双审通过 |
| **P1** | 后台图片上传（R2）：写稿台上传封面/设定图 | 未做 | ¥1.5–2 | 上传后读者页立刻显示 |
| **P2** | 写稿台三件：拖拽排序、预览、删除 | 只能改字 | ¥1.5 | 三步内完成一次改稿 |
| **P3** | 世界地图页（目前占位） | 占位 | ¥2–3 | 一张可缩放地图 + 地点卡 |
| **P4** | 其余 10 人设定原稿接入 | 只接了芙兰、琉玥 | ¥0.2/人 | 档案页 12 人全部有图 |
| **P5** | 阅读层细节：章节内脚注、生词卡 | 未做 | ¥0.8 | 长按/点击出释义 |
| **P6** | 运营件：RSS、访问统计、自动备份 | 未做 | ¥0.8 | 有订阅地址、有备份脚本 |
| **P7** | 自有域名（candied-ruin.com 之类） | 用 pages.dev | 域名费 | 绑定 + 301 |

**顺序理由**：P0 是内容，决定读者留不留；P1/P2 是作者效率，决定你能写多快；P3 是世界观补完；P4 是视觉密度；P5–P7 是长期运营。

## 五、明确不做的事（避免过度工程）

- 不做读者账号体系（P1 之后才考虑）——现在没有内容量支撑。
- 不做评论/弹幕——先把正文写好。
- 不做多语言。
- 不做“每日签到/积分”这类手游化功能。
- 不追第三方框架（保持零构建、纯静态 + 少量 JS）。

## 六、三条命令的执行方式（写进流程，不靠自觉）

| 命令 | 执行动作 | 落到哪里 |
|---|---|---|
| 人物必须对得上性格 | 每章交付前做“人物对表”：设定卡三行 vs 本章行为三行 | 双审第 1 项 |
| 每章写完要双审 | 编辑 6 项 + 作家 2 项，附“我不满意的地方” | 记忆 rules `0mvsf8hb` |
| 按地错风格但不照抄 | 只用它的手法（短段、信息跟人走、代价具体），不用它的设定与桥段 | `docs/reference-danmachi.md` |
| 让读者读得下去 | 唯一判据：读完这章想不想点下一章；交付时指出“哪段会让人放下” | 记忆 rules `0mvsella` |
