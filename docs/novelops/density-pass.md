# 推进密度补拍 · 作业说明（卷一二，ch1–22）

## 为什么做
用户判定：ch1–22 目前「一章只推进一件事」，读起来慢。结构问题不能靠改句子解决，要在每章里**多加一拍副线实动**，让这一章同时有两条线在动。

## 铁律（违反即返工）
1. **只加不改**：在既有场景里插入 60–160 汉字的动作段（3–8 行），不改主线事件、不改章末钩子、不删人、不增人物。
2. **副线只能从这一章「谁被瞒着」那一格长出来**：先读 `docs/char-matrix-ch1-22.md` 对应章行，把那一格里的秘密写成「差一点露出来」的一拍（例如有人问了一句、她手上停了一下、账上多了一笔对不上的数）。秘密**不许真的暴露**。
3. 只能动本批次的 md 文件；不许碰 `docs/`、`scripts/`、`public/`、`data/`、其它章。
4. 用 `edit` 或 `write` 改文件，禁止用 shell 重定向/`.Replace`/`Set-Content` 改中文正文。
5. 每章改完必须跑指标，并在简报里贴出改前→改后数字。

## 指标门（不许因补拍而跌破）
- 均句 11–16；叙述段短段 ≤72%（正文原值已在 54.8–74.2%，不许更糟）
- 对话汉字占比 ≤45%（原本就高的章不许再升）
- 「他说／她说」≤2/千字；破折号 ≤3/章；跨章重复段 0
- 冒号/分号密度不飙升；一章最多一处 `——`

## 跑指标
```
cd bubble-vanguard-app
export PATH="$HOME/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/node/bin:$PATH"
python scripts/tmp_struct_scan.py | grep -E "0(0|1|2)[0-9]\.md|TOTAL"
```
（`tmp_struct_scan.py` 只读；输出 `tmp_scan.json`，不要改它）

## 交付简报格式
每章一行：`chNN 插在「…」之后 ｜ +NN 汉字 ｜ 副线＝…（来自矩阵第 N 行「谁被瞒着」）｜ mean a→b / nshort x%→y% / dial m%→n%`
最后一行：`本批 m 章全部过门 / 失败章：…`

## 禁区
- 不写内心独白总结句（「她突然明白…」）
- 不写游戏词：副本、任务、系统、面板、等级、经验
- 不写「她很难过」式总结；付账必须可数
- 不在章首加时间状语
